# 自然语音与首声等待修复

沿用用户已选择的浏览器整段朗读方案，修复本轮明确提出的等待、机械音色和本地模型体验问题。用户确认此前满意的是电脑 Chrome；不以 Edge 的云端回退结果冒充 Chrome 原生验收。

## 已确认的原因

- 当前自动音色给系统本地声音更高分，可能压过自然声音；浏览器发声失败后统一使用讯飞备用音色，界面未显示本次实际引擎。
- 云端必须收齐完整音频再播放。实际同文对照中，供应商在 354 ms 完成，关闭连接又等待 1035 ms；把关闭等待限制为 150 ms 后，总耗时由 1389 ms 降到 429 ms，PCM 长度与摘要一致。数字来自本机直测，不是生产端到端承诺。
- 本地模型是真实的 Kokoro 发音与 Moonshine 识别，但进度被丢弃、失败状态不能有效重试、发音排在识别下载后，而且推理最长等待 60/45 秒。

## 方案

修复现有路线，继续使用一个完整原生 utterance 或一个完整 WAV。优先明确选择的音色，其次自然/神经/Google 英语声音，避免默认选择传统机械系统声。显示本次实际声音、准备/播放/失败及回退原因，不静默伪装选中的引擎。

云端保留完整波形、供应商完成标志和输入边界；把已完成响应的 WebSocket 关闭等待限制为 150 ms。正常完整音频不得因关闭握手拖延而继续阻塞。取消和未完成响应仍按失败处理。

本地模型保留为实验功能，明确用途、分别显示两个模型的状态和实际下载字节，可重试失败下载；显式选择本地发音时先准备 Kokoro，再准备 Moonshine。推理失败/超时销毁失效 Worker 并恢复可重试状态；TTS 预算 2 秒、ASR 预算 5 秒，发音未就绪优先使用可用的浏览器声音，再使用云端。聊天与评分仍在线，不宣传完整离线产品。

不恢复逐句/PCM 客户端拼接，不换供应商或增添凭据，不删除现有 ASR、评分、历史或本地模式。原生质量仍须在 Chrome 实测，主观听感不以回调代替。

## 验证

先复现回归再修复，覆盖自然音色选择、实际引擎与回退状态、关闭握手延迟且完整音频不变、进度/重试/优先顺序、失效 Worker 和取消/迟到结果。运行完整回归、静态检查、构建及一次独立审查；保留主工作区九个用户修改，提交作者 EthanLyu30，合并推送 main 并验证部署。临时诊断文件在验证后清理。
