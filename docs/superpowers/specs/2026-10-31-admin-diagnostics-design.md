# 看板可靠性与排查体验

## 已确认的问题

- 生产日志中的 `psycopg.errors.AdminShutdown` 导致已失效的池连接在下次查询时报错，既影响练习记录读取，也影响后台权限查询。
- 当前 1440 × 1000 桌面首屏默认限定流式对话，已有其他操作却显示零样本；小字号、低对比辅助文字和大面积空图让信息难以扫描。
- 概览与列表绑定 `Promise.all`，一项失败便隐藏另一项已成功的数据。历史失败只显示 HTTP 未知，没有异常类型线索。

## 本轮设计

延续现有暖白、深棕、珊瑚色及 Lucide 图标，不新增设计栈、外部服务或公共管理入口。

1. 默认近 24 小时、后端所有操作；浏览器来源切换时也展示该来源的所有操作。混合业务明确标注，性能比较须选同一种操作。
2. 四张紧凑指标卡：保留样本、成功率（浏览器为异常样本）、P95、失败/超时入口。模型 TTFT 保留在模型观测面板。
3. 图表按操作分组并提供图例，缩短图表区域；Trace 检索并入调用记录区域，提高首屏可见记录数。辅助文字至少 12px，表格和控件至少 13px，增加对比度。
4. 全局时间、来源、操作、模型、版本筛选影响全部数据。列表状态、慢请求排序和翻页只用于排查列表，不能把概览成功率变成“失败筛选下的 0%”。
5. 概览和列表分别报告加载失败，成功部分保持可用。刷新相同筛选失败时可保留旧数据，但明确标示上次结果；权限拒绝立即清除私有数据。
6. 详情展示来源、版本、HTTP 状态和异常类名。历史记录缺失异常类型时明确说明未知，不伪造根因，不因后续成功就标记“已修复”。

## 技术与隐私边界

- SQLAlchemy `pool_pre_ping=True` 在取用旧连接前检查有效性，不自动重放业务事务；数据库整体不可用和事务执行中断仍会如实报错。
- 新增两个可空字段 `error_type`、`error_cause_type`，启动时兼容迁移已有 SQLite/PostgreSQL 表；旧记录保持空值。
- 仅保留异常类名，不保存异常消息、SQL 参数、用户问答、音频、邮箱或凭据；原有 spans JSON 数组格式不变。
- 管理员服务端授权、no-store、来源隔离、取消统计、未知 usage/TTFT 和既有评分/历史记录逻辑保持完整。
- 1440 × 1000 桌面与 390px 手机宽度验收；不生成线上演示数据，不发起付费评分请求。

## 验收

失效池连接测试先失败后通过；已有遥测表无损迁移；异常类名可读且不泄露消息；旧记录仍可读。前端覆盖全量默认、列表筛选不污染概览、单面板故障、刷新旧数据标识、401/403 清空、详情新旧元数据。完成全量回归、独立审查及线上真实页面检查后合并部署。
