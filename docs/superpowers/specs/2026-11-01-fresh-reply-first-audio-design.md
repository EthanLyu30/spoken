## Exact diagnostic interface

Native optional fields apply only to `speech.native_start`: `reason` = started/startup_timeout/end_before_start/speech_error/speak_exception/cancelled; `error_code` = canceled/interrupted/audio-busy/audio-hardware/network/synthesis-unavailable/synthesis-failed/language-unavailable/voice-unavailable/text-too-long/invalid-argument/not-allowed/unknown. `state_before` and `state_after` are strict integers0–7 with paused=1, speaking=2, pending=4; omit when state is unavailable. `voice_type` = enhanced/remote/local/unknown, derived without recording voice names or URI. `voice_matched` is an optional strict boolean for an explicitly requested URI match, omitted for automatic choice. The client reports exactly one startup result per actual attempt.

New accepted client operations: `chat.first_text`, `chat.complete`, `chat.tail`, `speech.request_to_audio`. The three chat values are elapsed request-to-first-text, request-to-accepted-final-return, and last-delta-to-final-return; the fourth starts at typed submission after ASR, not at microphone stop. Existing `speech.first_audio` retains queue-construction timing and `voice.first_audio` retains call/ASR timing. Successful SSE done may include `timings` with whitelisted `llm_*` numeric stages/counters; the old data shape remains accepted by readers. No user content or arbitrary strings are permitted.
