# 即时纠错、点词词典与移动端朗读优化设计

日期：2026-07-16  
状态：已获用户口头批准，等待书面规格复核

## 1. 背景

Spoken 当前已经具备三组相关能力：

- 课后小结会调用 DeepSeek，生成语法纠错、推荐表达和学习建议。
- 跟读练习会调用讯飞 ISE，返回句子、单词和音素级发音分数。
- 划选单词或短语可以收藏到生词本，后端会按需生成中文释义和例句。

这些能力目前分散在课后报告、跟读评分和生词本中。用户在对话当下无法快速确认自己的表达，也不能直接点击聊天中的生词查看翻译。此外，部分没有英文浏览器语音的手机会退回云端朗读，当前云端音色和停顿处理仍可能产生逐词跳读感。

本设计把现有能力重组为三个互相独立但体验一致的功能：

1. 每条用户消息按需展开即时纠错。
2. 页面英文内容支持点词和划选短语查询。
3. 浏览器没有可用英文音色时，自动使用更自然、连续的讯飞朗读。

## 2. 目标

- 正常角色对话不被纠错分析阻塞或打断。
- 每条用户消息都能按需查看语法、表达和推荐改写。
- 语音输入的消息还能查看基于该轮原始录音的发音参考。
- 点击英文单词或划选英文短语即可查看中文词典信息。
- 词典结果可朗读、复制并收藏到现有生词本。
- 在没有可用英文浏览器音色的手机上提供连贯的云端朗读。
- 所有新增请求均按需触发，并有缓存、长度限制和失败降级。

## 3. 非目标

- 不在每轮发送后自动纠错。
- 不让角色扮演聊天模型在回复正文中充当语法老师。
- 不持久化用户录音、即时纠错结果或词典查询历史。
- 不把即时纠错替代现有课后小结；课后报告继续提供整段会话的综合反馈。
- 不提供音频波形编辑、人工教师点评或离线词典包。
- 不自动改写或替换用户已经发送的原句。

## 4. 用户体验

### 4.1 即时纠错

每条用户消息气泡下方显示“即时纠错”按钮。点击后，该消息下方原地展开一张卡片：

- 加载时只锁定这一张卡片，不影响继续聊天。
- 卡片始终显示原句和一条完整的推荐句。
- 有问题时，按“语法”和“表达”标注具体修改及中文说明。
- 没有明显问题时，显示“表达自然，无需修改”，推荐句与原句保持一致。
- 推荐句支持：
  - 朗读；
  - 复制；
  - 放入输入框继续练习。
- 再次点击按钮可折叠卡片；已经成功加载的结果不重复请求。
- 请求失败时只在该卡片显示错误和“重试”，不影响 Pip 回复或其他消息。

语音来源的消息额外显示“发音参考”：

- 总分、准确度、流利度和完整度；
- 逐词颜色；
- 可点开的逐音素偏差；
- 明确说明分数基于讯飞评测和识别文本，只作练习参考。

文字来源的消息显示“本句为文字输入，无法评测发音”。

如果一条消息由输入框中已有文字和随后录入的语音拼接而成：

- 文本纠错分析完整消息；
- 发音评测只分析该轮实际录入的语音片段；
- 卡片标注被评测的语音片段文本，避免把未朗读的文字算入发音分数。

### 4.2 点词词典与短语翻译

以下英文学习内容使用同一个可交互文本组件：

- 对话页中 Pip 和用户的消息；
- 即时纠错卡片中的推荐句和问题片段；
- 每日跟读句子；
- 课后报告中的纠错和好用表达；
- 历史会话中的对话文本。

交互规则：

- 轻点单个英文单词：查询该词。
- 鼠标拖选或手机长按选择最多 6 个英文单词：查询整个短语。
- 已存在有效文本选择时，短语查询优先，不再触发单词查询。

桌面端在触发位置附近显示浮层；窄屏设备使用底部弹层。卡片显示：

- 查询词或短语；
- IPA 音标；短语无法可靠给出整体音标时允许为空；
- 词性；短语无单一词性时允许为空；
- 简短中文释义；
- 一条自然英文例句；
- 例句中文翻译；
- 朗读、复制和“加入生词本”。

词典卡片打开后，点击遮罩、关闭按钮或按 Escape 可关闭。重复查询使用当前浏览器会话内缓存并立即显示。只有用户点击收藏时，才调用现有生词本写入接口。

### 4.3 移动端朗读

默认朗读策略如下：

1. 用户明确选择“讯飞云端”时，直接使用讯飞。
2. 用户选择或保留默认“浏览器语音”时，首次朗读最多等待 500 ms 让异步音色列表就绪。
3. 如果存在英文浏览器音色，使用当前选中音色或自动选择得分最高的英文音色。
4. 如果 500 ms 后仍没有英文音色，自动退回讯飞，不调用设备上的非英文默认音色。

自动退回讯飞时：

- 用户手动选择的讯飞音色优先；
- 未手动选择时使用 `x4_lindsey_formal`；
- 未手动设置语速时使用 58，未手动设置音调时使用 52；
- 设置页明确提示当前设备没有英文浏览器音色，实际朗读将自动使用讯飞。

讯飞音频继续使用“一次请求生成整句原始 PCM，再包装为单个 WAV”的方式，不切成单词或 MP3 小片段。现有固定 RMS 静音裁剪将改为保守的近零静音归一化：

- 只处理连续至少 120 ms、振幅接近数字零的区段；
- 普通低能量辅音和词内过渡不得被判定为静音；
- 被处理的词间停顿至少保留 60 ms；
- 开头和结尾只移除近零静音，不截断有声段；
- 标点处的自然停顿不追求完全消除。

最终参数必须使用公网讯飞真实样本验证，而不能只依赖合成测试波形。验收样本包括无标点短句、带逗号句子和带句号的两句回复。

## 5. 技术架构

### 5.1 即时文本纠错接口

新增：

`POST /api/turn-correction`

请求体：

```json
{
  "scenario_id": "cafe",
  "text": "I very like this coffee",
  "previous_partner_message": "How do you like the coffee?",
  "custom": null
}
```

约束：

- `text` 去除首尾空白后长度为 1–600 字符。
- `previous_partner_message` 可空，最大 600 字符。
- 普通场景必须存在；自定义场景沿用现有 `CustomScene` 结构。

响应体：

```json
{
  "original": "I very like this coffee",
  "natural": false,
  "suggestion": "I really like this coffee.",
  "issues": [
    {
      "kind": "grammar",
      "original": "very like",
      "replacement": "really like",
      "note": "very 通常修饰形容词；修饰动词 like 时用 really 更自然。"
    }
  ],
  "explanation": "意思表达清楚，调整副词后会更自然。"
}
```

规则：

- `kind` 只允许 `grammar` 或 `expression`。
- `suggestion` 始终是完整、可直接使用的英文句子。
- `natural=true` 时，`issues=[]`，`suggestion` 等于规范标点后的原句。
- 模型只分析当前句子，前一条 Pip 消息仅用于理解语境。
- 使用独立、低温度、结构化 JSON 的 DeepSeek 调用，不修改现有角色扮演提示词。
- 模型输出无法解析时返回 503，前端提供单卡重试。

### 5.2 发音评测复用

继续使用现有：

`POST /api/pronunciation?text=<recognized-spoken-text>`

不新增录音存储接口。前端保留本轮 16 kHz 单声道 PCM，并在用户点击即时纠错时把以下两个请求并行发出：

- `/api/turn-correction`；
- `/api/pronunciation`，仅当该轮有语音 PCM 和对应的识别文本。

文本纠错成功、发音评测失败时，仍完整显示文本结果，并在发音区域提供独立重试。

### 5.3 对话页临时语音元数据

聊天接口仍只接收现有 `ChatMessage[]`。对话页新增独立的本地元数据表，以消息数组下标为稳定键：

```ts
interface UserTurnMeta {
  source: "typed" | "voice" | "mixed";
  spokenText?: string;
  pcm?: ArrayBuffer;
}
```

- 按键录音停止后，先保留 PCM，再做 ASR，最后把消息下标与元数据关联。
- 通话模式把 `CallCallbacks.reply` 改为同时接收 `userText` 和该轮 `pcm`，消息进入列表时立即关联。
- 最多保留最近 8 条有 PCM 的用户消息；加入第 9 条时释放最旧的 `ArrayBuffer` 引用。
- 页面卸载、结束会话或刷新时清空全部 PCM 引用。
- PCM 不进入 Zustand、localStorage、会话保存请求或日志。

即时纠错状态同样按消息下标保存，但只包含加载状态、结果和错误，不持久化。

### 5.4 词典接口

新增：

`POST /api/dictionary/lookup`

请求体：

```json
{
  "query": "run into"
}
```

约束：

- 规范化连续空格和首尾标点。
- 必须包含英文字母。
- 最多 6 个空格分隔词，最多 80 个字符。

响应体：

```json
{
  "query": "run into",
  "phonetic": "",
  "part_of_speech": "phrasal verb",
  "meaning": "偶然遇见；碰到",
  "example": "I ran into an old friend at the station.",
  "example_zh": "我在车站偶遇了一位老朋友。"
}
```

后端使用低温度结构化 DeepSeek 调用，并维护一个进程内、大小为 512 条、有效期 24 小时的 LRU 缓存。缓存键为小写、压缩空格后的查询内容。模型失败返回 503，不写空缓存。

前端维护浏览器会话级 `Map<string, DictionaryEntry>`：

- 相同规范化查询直接返回缓存。
- 相同查询的并发请求合并为一个 Promise。
- 用户打开另一查询时取消旧的界面请求；旧请求即使完成也不能覆盖当前卡片。

收藏时复用现有 `POST /api/words`，写入：

- `text = query`
- `meaning = meaning`
- `example = example`
- `kind = "word"`（单词）或 `"phrase"`（两个及以上单词）

后端和前端现有 `kind` 字段接受字符串，因此不需要数据库迁移。

### 5.5 前端组件边界

新增或调整以下职责明确的单元：

- `InteractiveEnglishText`：把可点击英文单词包装为按钮，同时保留正常复制和文本选择。
- `DictionaryOverlay`：负责全局单词点击、短语选择、定位、加载、缓存展示和关闭。
- `TurnCorrectionCard`：负责单条消息的纠错、发音并行加载与结果展示。
- `PronunciationFeedback`：从现有 `PronounceButton` 抽取可复用的分数、逐词和逐音素展示。
- `dictionary.ts`：查询规范化、会话缓存和并发去重。
- `turnCorrection.ts`：单条纠错请求状态所需的纯类型和辅助函数。

现有 `WordCollector` 的“选择后只显示收藏按钮”行为由 `DictionaryOverlay` 取代；收藏仍通过 `useWords` 完成。不得同时保留两个选择监听器，以免手机端弹出两个浮层。

## 6. 错误处理与降级

- 即时纠错和 Pip 回复完全解耦；纠错失败不会重发聊天消息。
- 文本和发音结果独立：任意一项成功即可显示。
- 没有 PCM、PCM 已因 8 条上限被释放，或消息来自文字输入时，不请求发音接口。
- 词典查询失败时保留用户选择，显示重试按钮。
- 剪贴板 API 不可用时使用临时文本选择与复制命令作为降级。
- 朗读失败时显示非阻塞提示，不改变消息或词典内容。
- 浏览器音色加载超时只影响本次引擎选择；后续 `voiceschanged` 到达后，下一次朗读可恢复使用浏览器英文音色。

## 7. 隐私、安全与成本控制

- 原始录音只存在浏览器内存，最多 8 轮，离页即释放。
- 不向数据库、分析日志或课后会话记录写入录音。
- 纠错和词典请求按用户点击触发，不自动对每条消息调用模型。
- 后端对纠错文本和词典查询做严格长度限制。
- 词典使用前后端两级缓存；即时纠错按消息缓存，避免重复收费。
- 所有新增前端请求沿用 `X-Client-Id` 和可选登录令牌头。
- 模型提示词要求仅返回结构化数据，前端按普通文本渲染，不使用 `dangerouslySetInnerHTML`。

## 8. 可访问性

- 单词按钮仍显示为行内文本，具有可读的 `aria-label`。
- 即时纠错按钮、朗读、复制、收藏和关闭按钮均有明确中文标签。
- 加载状态使用 `aria-live="polite"`；请求错误使用 `role="alert"`；流式聊天的局部更新不进入这两个区域。
- 词典浮层获得焦点；Escape 关闭后焦点返回触发单词。
- 颜色不是发音好坏的唯一提示，同时显示分数和文字说明。
- 底部弹层不遮住系统安全区，支持键盘和触屏滚动。

## 9. 测试策略

### 9.1 后端

使用 `pytest` 增加：

- 单条纠错成功、自然句、语法问题、表达问题。
- 未知场景、空文本、超长文本、无效模型 JSON 和模型错误映射。
- 词典单词、短语、规范化、长度/词数限制。
- 词典 LRU 命中不重复调用模型，过期后重新调用。
- 讯飞静音归一化只缩短真实近零长停顿，不删除低能量有声段。
- TTS 仍返回单个有效 WAV，并遵守用户音色、语速和音调覆盖。

### 9.2 前端

引入 Vitest、React Testing Library、User Event 和 jsdom，增加：

- `InteractiveEnglishText` 点击单词并保留标点。
- 文本选择优先于单词点击。
- 词典规范化、缓存、并发去重和旧请求不覆盖新查询。
- 纠错卡文本输入不请求发音。
- 语音输入并行请求文本和发音，任一失败时另一项仍显示。
- mixed 输入只用 `spokenText` 做发音参考。
- 录音元数据超过 8 轮时淘汰最旧 PCM，卸载时清空。
- 浏览器有英文音色时使用浏览器；没有英文音色时在 500 ms 后使用讯飞。
- 用户选择的讯飞音色、语速和音调覆盖自动默认值。

### 9.3 完整验证

- 后端全量 `pytest -q`。
- 前端 `npm run test -- --run`。
- 前端 `npm run lint`、`npm run typecheck`、`npm run build`。
- 桌面浏览器和手机宽度手动检查即时纠错、底部词典、文本选择和焦点返回。
- 通过公网后端获取三组真实讯飞音频，检查连续性、停顿长度和首尾是否截音。
- 部署后验证 `spokenai.org`、Vercel 备用域名和 Render 健康接口。

## 10. 验收标准

- 每条用户消息都有可折叠的“即时纠错”入口。
- 点击后得到原句、完整推荐句和具体中文说明；自然句不会被强行改写。
- 正常聊天可在纠错加载期间继续进行，Pip 回复不等待纠错。
- 语音消息显示发音参考；文字消息明确说明无法评测。
- mixed 消息只评测真实录入的语音片段。
- 点击单词或选择最多 6 词短语可看到中文释义、例句及翻译。
- 词典结果可以朗读、复制和收藏，重复查询不重复调用。
- 无英文浏览器音色的设备会自动使用 `x4_lindsey_formal` 云端音色。
- 云端朗读为单个连续 WAV，没有逐词文件拼接；真实样本不存在明显逐词跳读或截音。
- 录音不会在刷新、离页或会话保存后保留。
- 新增测试与现有全量测试全部通过后，代码推送到 `main` 并由现有 Vercel/Render 自动部署。
