# 视频参考与 45 秒口语范例

用户要求 DeepSeek 参考博主的视频范文再优化，兼顾每题 45 秒、临场思考和停顿，表达自然、简洁，不堆词或冗长。沿用现有 190 组题库和两个练习模式。

## 方案

采用「视频范文提炼为短要点，评分时交给 DeepSeek 参考」：从视频尾部 Sample Answers 画面核对每题的回答角度，保存原创概括和来源时间；不保存或展示逐字范文。DeepSeek 结合这些要点、题目与学习者的作答，生成适合自然说完的示例。

固定预生成单一范例容易与学习者的合理立场不同；继续仅按题目生成无法满足视频参考要求。采用当前方案可保留视频中的多种角度，并优先沿用学习者合理的立场和具体例子。

目前核查发现 #190 每题有三种回答角度；这些是可选思路，不是评分标准。早期 #1–#16 的标题与描述没有范文说明，需核对实际尾部画面后标为无范文；其余期数也以实际画面核对为准，不凭标题假定已收录。

## 数据

- 新文件 `backend/app/data/inspire_answer_references.json`：`playlist_url`、`reviewed_at`、`sets`。
- 每条：`set_id`、`episode`、`source_url`、`status`（`reviewed` / `not_provided` / `unavailable`）、`answers`；无范文/无法核实时记录 `reason`。
- `reviewed` 必须四条答案，`question_index` 为 1–4；每条 `notes` 是简短原创概括，覆盖视频提供的主要角度，`timestamp` 为对应画面的源时间，格式为MM:SS或HH:MM:SS。
- 文件加载时验证套题身份、来源与现有题库一致；未核实内容不会冒用视频来源。
- 参考资料只用于完成练习后的评分请求，不放进题库目录或提问接口，防止模拟提前看到答案。

## 生成与时长

- 每题仍为 45 秒。范例目标 **55–75 词**，通常 3–5 个短句：直接回答、给一个清楚的理由或具体细节，必要时简短收束。多分支题保留所有必要分支。
- 常见词、自然口语、少量连接词；避免套话、复杂辞藻、长开头和过多论点。不要求每道题机械套同一模板。
- 优先保留学习者合理立场与例子；视频提供的不同角度均可成立，不按是否同意范文评分，不把参考范文作为唯一正确答案。
- 评分仍只基于转写内容，不能声称评价发音、实际语速或真实停顿，也不能把范例中的经历说成已知的学习者事实。
- 服务端计算英文词数；超过 75 词时最多一次仅针对范例的压缩请求，保持已生成分数和点评；不按字数硬截断句子。压缩仍失败时走现有反馈重试流程，不返回超长或伪造范例。
- 时长按约 110 词/分钟加 4 秒停顿估算，界面明确为估算，不保证每个人的实际朗读时长。

## 接口与界面

- `/api/interview/score` 新增可选 `set_id`。有 ID 时必须与四道题匹配；旧客户端没有 ID 时仅在完整题组唯一匹配时关联资料，其他情况照常评分、标为 AI 生成。
- 结果新增服务端确定的 `sample_source`（`video_reference` / `ai_generated`）、`sample_source_url`、`sample_word_count`、`sample_estimated_seconds`。不信任模型提供的来源或词数。
- 结果页显示词数、估算秒数和「参考视频思路 · AI 改写」来源链接；无视频资料显示「AI 口语示例」。旧历史没有新字段时仍正常回顾，不能误标成视频来源。

## 验收与保留

核对真实视频画面、套题顺序、范文缺失及不同立场。测试来源对齐、超长范例修复、修复失败、恶意/错位 ID、旧协议和旧历史兼容；实际调用现有 DeepSeek 检查范例长度、口语风格和观点保持。完成后做桌面/414px 自动验收，按 EthanLyu30 署名提交、推送 main 并检查上线。

继续使用当前项目与依赖，在任务分支工作，保留用户未提交的部署/运维修改。原始视频帧、OCR、辅助脚本、测试数据库与本轮缓存在核验最终数据后清理，只保留题意要点、维护代码和验收文档。
