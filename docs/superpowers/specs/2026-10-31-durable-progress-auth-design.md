## Progress contract

Introduce a small permanent learning-event journal, independent of retained conversations (200), practice details (1000), and current vocabulary. Preserve existing detail retention, recent charts, insights, 0–5 interview scores, video references and enhanced answers. The journal contains ownership, source receipt, UTC occurrence time and minimal score/scenario/word identity metadata; never conversation text, answers, tokens or audio. New journal entries and their source activity must commit atomically.

Events are session, practice, word_collected and word_reviewed. New activity keys are UUIDs; legacy backfill keys are stable and distinct. Conversation receipts also enforce a permanent owner/client_session_id unique constraint, including after detail pruning. A duplicate save returns the original result or a minimal original receipt with detail_available:false if its detail has expired; it never creates another practice or changes the original score/date. Legacy callers without an idempotency key keep their existing behavior.

Persist earned badge keys independently. Once earned, badges remain earned despite pruning, vocabulary deletion, broken streaks or a later device timezone change. Badge keys and thresholds: first_conversation(1), streak_3, streak_7, conversations_10, words_10, words_50, reviewed_words_10, pronunciation_90, interviews_3, conversation_90, scenarios_5, level_3. Collection/review word identities follow existing trimmed, case-sensitive vocabulary semantics. Deleting/recollecting the same word does not farm vocabulary XP.

Stats keep existing fields: total_sessions and total_practice become journal lifetime counts; words_count remains current word-bag size; XP remains sessions*40 + practice*15 + lifetime distinct collected words*5, without XP for review. today_count includes completed conversations and speaking practice only. streak_days includes speaking, word collection and review. A forgotten review (box=0) remains a valid learning activity. Add earned_badges:string[], timezone:string and local_date:YYYY-MM-DD. Use longest proven historical streak to unlock streak badges, current streak for the live streak display.

Accept optional X-Timezone with an IANA timezone; validate using ZoneInfo, fall back to UTC for absent/invalid values, and include tzdata for portable deployment. Store UTC and convert occurrences using the request timezone, accounting for DST. Browser requests send the current device timezone. Cache identity includes local day/timezone and refreshes on midnight and focus/visibility changes, preserving existing partial-load and abandoned-refresh behavior.

Run an idempotent, transaction-protected, versioned backfill after existing DB migrations, using the passed engine connection. Import only surviving old data, including last_reviewed even if box=0; unknown review time can count as review evidence but cannot invent a learning day. Already deleted/pruned history and overwritten older review times cannot be recovered. Registration transfers journal entries and merges earned badges in the same claim transaction, resolving duplicate receipts safely. Guests must never gain access to claimed account data.

## Account contract

Install synchronization before initial render; reconcile current durable token on token-key storage events, storage.clear and optional BroadcastChannel invalidations. Ignore stale event payloads and duplicate notifications, never broadcast credentials or received notifications. Keep the existing current-page RAM fallback if storage is denied; do not claim such unpersisted credentials can automatically synchronize to another page.

An identity change synchronously invalidates prior work and clears previous-user words, progress and session/report state. Owner-sensitive routes are gated while resolving the new user and keyed by generation. Preserve ordinary guest use, RAM login/logout, transient-refresh behavior, preferences and already-dispatched valid saves. Guard old refresh/401/profile/auth completions, overlapping login attempts, vocabulary mutations, interview grading, report retries and conversation unmount feedback/save chains with a captured generation. Old unsent work must never use new credentials. No-token startup remains immediate; cached optional user/word data must not flash a mismatched account. Do not solve this by rehydrating unrelated Zustand persisted caches on storage events.
