# 云端整段语音按需预连接设计

## 目标与依据

用户要求缩短新回复的云端建连和完整音频等待，不升级付费配置、不影响现有功能；对比前后耗时，继续实际聊天首声验收，通过后 push main。保留当前提供方、音色、语速、完整 WAV、浏览器原生优先和本地模型的显式选择。

线上一次分段记录：建连 1275.5 ms，首 PCM 累计 1650.2 ms，完整 PCM 累计 2027.3 ms，关闭 151.0 ms；三条新回复完整音频获取中位数 2843.8 ms。瓶颈证据指向连接与传输等待，未证明免费实例算力饱和。

本机协议核验：先建立讯飞连接，空闲 1513.5 ms 再提交一次全文，正常取得终帧及 156998 字节 PCM。仅证明可在全文前建连，不作为线上速度成绩。[提供方协议](https://www.xfyun.cn/doc/tts/online_tts/API.html)规定一次提交全文、收齐终帧后关闭；不采用完成连接的循环复用。

## 方案取舍（实施判断）

- 仅削减关闭等待：上限约 150 ms，不能解决已测的约 1.28 秒建连。
- 把音频分片提前播放：与用户已确认的整段播放方向冲突，不采用。
- **采用按需预连接**：新回复生成期间，在服务端提前握手；完整文本到达后仍由现有 `/api/tts` 生成一个 WAV。增加一个限额、短时、一次性的连接准备机制；未命中时保持原路径。

此取舍由实施者依据既有授权作出，不表述为用户另行选择了具体 API 设计。

## 服务端

1. 应用 lifespan 拥有 `TtsWarmupPool`。`POST /api/tts/prepare` 不接收文本，只尝试占用一个准备名额并立即返回服务器生成的 32 位随机十六进制 ticket；返回 `Cache-Control: no-store`。未配置服务、限额或池不可用返回可回退的失败状态，不暴露提供方凭据、URL 或错误原文。
2. 池最多保留 4 个未消费连接，从预约开始 4 秒失效；启动速率最多 4 次/秒。无常驻循环预热，无新合成文本、身份记录或用户内容缓存。`discard(ticket)` 原子失效并安排受池拥有的异步清理，不等待握手/关闭；失败、失效和 shutdown 都关闭资源并读取任务异常，shutdown 排空清理任务。
3. `TtsRequest` 可选 `warmup_ticket`。旧请求不带字段时保持既有逻辑；错误格式仍按输入校验拒绝。
4. 仅取用已握手成功、未过期、仍打开的连接，ticket 在取用时即销毁。正在连接、失败、失效、不存在、重复使用均立即退回普通连接，不在语音关键路径等待准备任务。避免准备失败叠加一次等待。
5. 有效取用后的连接由该次合成拥有，全文只发一次，保留现有错误、30 秒合成期限、终帧校验、PCM 顺序及 WAV 包装；当前音色与速度仍在 `/tts` 请求时确定，不被准备时的偏好锁定。
6. 后台任务显式使用清空的 ContextVars 上下文，不借用已经结束的请求 trace 写阶段；接入固定数值指标 `tts_warmup_hit/miss/age/connect`，区分准备期建连与当前合成期建连，绝不把重叠时钟累加为总耗时。
7. 文本缓存命中时仍及时释放传入 ticket，避免占用至失效。准备连接不承载签名下发或新的提供方访问权限。

## 前端

1. 独立 `cloudSpeechPreparation` 模块提供可释放的一次性准备对象；请求有短超时，失败静默回退，不阻塞模型请求或抢占正在播放的内容。
2. 仅未静音的打字/录音发送及通话普通接口回退的 `prepareSpeech` 新回复准备流程触发：明确云端引擎，或浏览器/本地回退预计无英文音色且本地模型未就绪。已有英文音色的浏览器路径、已就绪本地模型、开场白、手动重播和设置试听不新增准备请求。通话现有流式队列本轮保持原状，不为全部消费者默认增加网络副作用。
3. 最终需要云端时同步取出已返回的 ticket；未返回即放弃，不等网络。把 ticket 随完整文本附到原 `/api/tts`。最终若改用浏览器或本地，准备取消；服务端未消费资源最多存活 4 秒。
4. 取消、静音、认证变化、旧轮次、卸载、声音偏好改变仍由既有 preparation/controller 生命周期清理。请求全文只发送一次，不调用切片音频端点。
5. 旧后端不支持 prepare 时（404 等），正常 `/tts` 不带新字段，继续工作。

## 验收

- 单元及路由覆盖：尚未准备好不阻塞、ready 一次取用、失败/过期/关闭、容量/速率、shutdown、未知 ticket 回退、PCM 不改变、参数不冻结、取消/静音与自然音色路径。
- 全量后端 pytest；前端 test、lint、typecheck、build。真实外部服务仅用于限量计时，不进入自动测试。
- 线上固定三段全文，交替普通与提前准备模式，各两轮；逐条保留耗时、命中和 Server-Timing。再以真实新回复确认模型等待与完整音频等待能重叠；不以等待固定时间的探针冒充真实聊天。
- 浏览器首声仍必须实测。同条交互关联首字、全文、播放回调；实际出声另核验。浏览器工具仍不可用时明确保持未完成，不能因 API 提速就宣告端到端验收通过。
- 临时脚本、缓存和预览在验证后清理；保留用户原文件及未知归属文件。
