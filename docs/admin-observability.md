# Spoken 私有运行看板

入口：`/admin`。只对服务器授权的现有账号开放。普通用户没有导航入口，直接调用 `/api/admin/*` 也会被后端拒绝。登录返回的 `is_admin` 仅影响显示，不是授权依据；篡改它不能读取后台数据。

## 首次授权

Render 免费实例没有 Shell。推荐在 Render 后端服务的 Environment 中临时配置：

```text
ADMIN_BOOTSTRAP_EMAIL=YOUR_EXISTING_ACCOUNT_EMAIL
```

替换为自己已经注册、正在使用的 Spoken 登录邮箱，保存并重部署。启动时只查询当时已经存在的账号，原子地保存其用户 ID 和一次性标记；不会创建账号，也不会因为后续有人注册相同邮箱而授权。即使这次未找到账号也会消耗该邮箱的标记，请先确认账号已注册，再配置。若填错，改成真正的现有账号邮箱。

成功后删除这个临时环境变量；权限留在数据库。相同配置在重启后不会恢复已撤销的角色。[Render 免费服务没有 Shell 的说明](https://render.com/docs/ssh)。

如果部署时账号尚未注册，这次配置也已经被消耗。先确认账号已经存在，再由服务器管理员在 Render 新增一个**新的尝试编号**：

```text
ADMIN_BOOTSTRAP_ATTEMPT=YOUR_NEW_ATTEMPT_ID
```

编号最多 128 个字符，每次明确重试使用新值。每个邮箱与编号的组合只消费一次，账号不存在时也会消费；同一编号重启不会自动补授权，也不会恢复撤销的角色。不填写编号时兼容原有标记。这是服务器配置操作，没有网页或注册接口可发起授权。成功后删除 `ADMIN_BOOTSTRAP_EMAIL` 和 `ADMIN_BOOTSTRAP_ATTEMPT` 两项临时配置。

有服务器 Shell 或安全数据库运维环境时，也可在应用 backend 工作目录中执行：

```sh
python scripts/admin_user.py --email YOUR_EXISTING_ACCOUNT_EMAIL
python scripts/admin_user.py --email YOUR_EXISTING_ACCOUNT_EMAIL --grant
```

第一条只核对已存在的账号并返回用户 ID / 是否为管理员；第二条才按用户 ID 写入管理员关联表。邮箱参数请替换为自己的现有登录邮箱。脚本不创建账号，不修改密码或学习数据，不打印邮箱、密钥、连接串。不要把真实邮箱提交到仓库。服务器必须使用实际生产数据库；本地 SQLite 的用户 ID 不等同线上用户 ID。

授权后可在 `/admin` 点击「刷新账号权限」，或重新登录，桌面导航出现「运行后台」。刷新只从服务器读取当前账号角色，所有管理员查询仍验证 JWT 和数据库名单，并返回 `Cache-Control: no-store`。

未配置一次性绑定、也未执行服务器授权前，后台默认锁定。部署不会自动给任何人授权，也不会信任第一个注册账号。已有持久化数据库用于存放名单和采集数据；临时 SQLite 与原项目一样会随实例重建丢失。

## 怎样定位慢请求

1. 默认查看近 24 小时的后端所有操作，便于发现非对话接口的失败。混合业务仅看整体分布；先切换到相同业务操作、模型和发布版本，再比较 P50/P95/P99、首文本等待和请求成功率。
2. 点「失败 / 超时」卡中的分类入口，或在调用记录中勾选慢请求优先、筛选状态，点 Trace ID 查看阶段瀑布。列表状态、排序和翻页不改变顶部概览的统计分母；全局时间、来源、操作、模型及版本仍同时作用于概览和列表。并发/父子阶段可能重叠，不能把各条耗时相加。
3. 切换「浏览器体验」查看整轮语音、识别收尾、首声及播放完成。整轮首声从 VAD 检测到说话结束起计；语音队列首声从创建队列起计，不含之前的识别。「播放阶段（首声至结束）」单独记录首声开始到队列结束的墙钟时间，包含句间等待；未开始播放不产生这项样本，失败和取消保持相应状态。原有完成总耗时仍保留，不等同服务生成时间，不能把重叠阶段相加。
4. 有匿名交互编号的记录可点「同一轮交互」找到对应识别、聊天和 TTS 请求。一个 HTTP 请求是一条独立 Trace，请求内 span 使用同端单调时钟；交互编号仅关联多条 Trace，不伪装成跨机器同步时钟或标准 OTLP 导出。

概览与列表分别加载，单项失败不会遮挡另一项已成功数据。相同筛选刷新失败时会明确标示保留的上次结果；改筛选、换账号或服务器拒绝权限时清除不适用的数据。权限拒绝还会取消其他在途私有请求。

## 数据库连接与错误线索

托管 PostgreSQL 可能主动终止空闲连接，日志表现为 `OperationalError` / `AdminShutdown`。引擎使用 [SQLAlchemy pre-ping](https://docs.sqlalchemy.org/en/20/core/pooling.html#disconnect-handling-pessimistic)，在取用旧连接时检测并替换。它不会重放业务写入，也不能掩盖数据库整体不可用或执行中的事务中断。

遥测表新增可空的 `error_type` / `error_cause_type`，启动时对已有 SQLite/PostgreSQL 表做可重复的加列迁移，历史记录保留空值。异常只记录类名，不存异常消息、SQL 参数或业务内容；旧 spans JSON 数组格式保持不变。详情会展示已采集的异常类名，以及来源、版本和实际观察到的 HTTP 状态。

历史失败缺少异常类型或 HTTP 状态时明确显示未采集，不能只凭 6ms、空阶段等信息推断根因。失败记录不会因上线修复而删除；查看最新同操作请求与服务端日志来判断是否仍然发生。

## 数据口径

### 模型与费用

看板直接返回服务器当前配置的语言模型（目前仅允许 `deepseek-flash`），以及核对日期、官方映射和公开单价。当前快照核对于 2026-10-31，来源为 [DeepSeek 官方](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)：人民币/百万 Token，缓存命中输入空闲/高峰为 0.02/0.04，未命中输入 1/2，输出 4/8。价格快照在 `app/services/model_pricing.py` 维护，不承诺自动跟随供应商调价。

费用参考区间按已完整采集的 Token 和已知模型计算：下界采用全部输入命中缓存及空闲价，上界采用全部输入未命中及高峰价。它用于参考预算，不是历史实扣账单，不包含赠送、优惠或讯飞语音资源包。失败/取消但已返回用量的请求仍计入；用量不全和未知模型明确计数，缺失不补零。浏览器体验样本不计 Token 和模型费用。普通数据读取接口不会标成 AI 调用。

### 游客与活跃用户

公开页面首次打开、路由或登录身份切换时尽力上报，失败不影响页面或语音。游客 UV 按匿名浏览器标识在选定滚动时间范围内去重；登录活跃按账号去重。同一浏览器重复打开、同账号跨设备不会增加对应去重数。两项可能因登录前后重叠，不相加为总人数，也不是实时在线数。

访客只受时间范围影响，技术来源、操作、模型、版本和调用状态不改变访客口径。服务端核实账号，排除已登录管理员；`/admin` 不发访问事件。无效 JWT 不会降为游客，缺失稳定标识的访问不计 UV。跨站点域名、更换浏览器、清除站点数据或轮换服务器签名密钥可能改变匿名标识。

数据库只存每日服务器时间、类型和 HMAC 摘要，不存原始浏览器 ID、用户 ID、IP、邮箱、URL 或内容。UTC 日内原子 upsert，跨日按摘要 distinct，乱序更新保留最早/最晚时间。仅管理员聚合接口可读取计数；不上报的访问可能漏计。采集开始时间会显示，上线前无法补算。

### 自动清理

调用记录默认保留 14 天/20,000 条，后端和浏览器分别占 75%/25% 预算；访客日活动另有独立 20,000 条容量目标（`VISITOR_MAX_RECORDS`），同样按 `TELEMETRY_RETENTION_DAYS` 过期。PostgreSQL 并发写入时访客容量可能短暂超出目标，下次写入或周期清理会收敛。达到容量时显示数据可能不完整。

除了每次写入执行保留限制，后端启动时及运行期间每小时会独立清理，不依赖新请求到达。免费实例休眠或停止期间任务暂停，下次启动补清理。看板显示上次成功时间及本进程失败次数。清理只针对遥测与访客表，不删除用户、管理员、学习记录或评分历史。

- 请求成功率：成功 /（成功 + 失败 + 超时），取消单列。HTTP 4xx/5xx 和 HTTP 200 后的已知流中断都不算成功。
- P50/P95/P99：nearest-rank，基于当前筛选后的保留样本；没有样本为 `—`。不平均各小时/各操作的分位数来得到总体分位数。
- 模型 TTFT：模型请求开始至首个非空文本；只有流式调用可实测。非流式评分不填写虚假的首文本时间。
- Token：仅在一次请求中所有已记录模型调用都提供完整 usage 时计量；未知不按零。升级答案修复调用在同一请求内合计，不增加模型调用。费用未配置可靠计价依据时不显示金额。
- 浏览器上报是不可信、可能不完整的体验样本，与可信后端统计分开；不能根据「首声成功事件」推算所有用户的播放成功率。静音、离页、浏览器拦截和断网都可能导致样本缺失。
- 只记录操作模板、时长、状态、模型、Token、重试尝试编号等白名单元数据。不记录问答、音频、完整异常、请求正文、认证头、签名 URL 或邮箱。

## 开销和保留

配置（均为后端环境变量，可保持默认）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `TELEMETRY_ENABLED` | `true` | 是否启用后台采集 |
| `TELEMETRY_RETENTION_DAYS` | `14` | 保留天数，允许 1–90 |
| `TELEMETRY_MAX_RECORDS` | `20000` | 合计保留预算，允许 100–100000 |

保留预算 75% 用于后端 Trace、25% 用于浏览器样本，避免浏览器上报挤掉可信后端记录。达到预算后，时间窗可能不完整；页面明确提示，所有计数与分位数基于现存记录。清理只作用于 telemetry 表，原学习记录不受影响。

根请求和 span 最多记录 64 个子阶段；后台写入使用 1000 条有界队列、最多 100 条一批。丢弃数和写入错误数为当前进程启动后的值，不是假装持久的全局累计。浏览器载荷最多 4096 字节、同连接来源每分钟最多 180 条，采集请求两秒后取消，失败不阻塞语音或页面。管理员查询不会被自身采集。

后端发布号采用 Render 的 `RENDER_GIT_COMMIT`，浏览器发布号采用 Vercel 构建时 `VERCEL_GIT_COMMIT_SHA`；缺少时显示未知或开发环境，不猜测版本。

## 当前范围

本看板监测 Spoken 自己的运行，不包含供应商内部不可见排队时间、独立多 Agent 编排或 Codex 执行工具的策略判断。工具执行前被拒绝的请求没有到达后端，不会生成业务 Trace。

后端 Trace 当前覆盖 HTTP 请求。WebSocket 中继内部还没有独立的服务端根 Trace；直接连接和中继连接的识别收尾耗时由浏览器分别上报，属于体验样本。流式响应在连接断开时记为取消，正常响应耗时截至最终响应体成功发送，不含响应后的清理工作。只有整段播放正常完成才记录 `speech.complete` 成功，已开始后失败也会记为失败。

实时通话在流式 ASR 不可用而改用完整录音识别时，同样记录 `asr.transcribe` 总耗时，并保留本轮选择的云端引擎；不会因本地模型随后就绪而切换这条降级请求。`asr.finalize` 仅表示已建立流的收尾等待，与整段录音识别总耗时含义不同。

在页面顶部粘贴响应头 `X-Trace-Id` 的 32 位编号可直接查找已保留的调用，不受当前表格页码影响；查找和详情始终重新验证管理员权限。
