# 浏览器朗读无声：恢复逻辑与验收边界

验收时间：2026-11-04 至 2026-11-05，Windows。未升级付费配置，未恢复讯飞朗读。

## 已确认的问题

1. Edge 的 Ava/Jenny Online (Natural) 在隔离的原生朗读测试中也出现 `end` 早于 `start`，且系统输出设备没有相应音频信号。应用无法修复微软音色服务本身，不能把 `end` 当作播放成功。
2. 内置浏览器最初只暴露 Huihui、Kangkang、Yaoyao 三个中文音色。旧版 SAPI 能使用 Zira Desktop，并不代表浏览器能使用英语音色：现代 OneCore 英语朗读组件当时未安装。
3. 经用户授权安装 `Language.TextToSpeech~~~en-US~0.0.1.0`，DISM 返回成功且无需重启 Windows。新启动的系统 WinRT 查询能列出 David、Mark、Zira 三个英语音色。正在运行的内置浏览器刷新和新建页面后仍只有旧中文列表；用户选择稍后重启 Codex，因此英语真实出声未完成验收。

上述结果不能证明微软在线音色存在全局故障，也不能据此认定免费后端配置是无声的原因。Windows 全局代理、系统音量、界面语言均未改变。

## 代码修复

- 保留选中的音色及原有自然音色优先规则。
- 已知在线音色在本段原生 `start` 之前遇到启动超时、提前结束或明确的音色/合成/网络错误时，每条回复最多恢复一次，使用浏览器实际列出的本机英语音色。
- 权限拒绝、主动取消或中断不触发换音色。已经开始朗读的内容不重播；流式模式只恢复尚未读出的剩余文本。
- 回退失败后停止，不轮流尝试所有音色，不以中文音色代替英语，不修改持久化音色偏好。
- 界面说明临时使用系统英语音色；无英语音色时给出设备语音设置提示并记为失败。
- 不新增云端 TTS 请求、模型下载、供应商切换或收费配置。

恢复逻辑仍保留原有 5 秒启动看门狗。在线音色挂起时，恢复最多还会先等待这个期限；本次没有将超时时间调短，避免误伤慢速但可用的自然音色。

`chat.first_text` 是浏览器请求至首段文本，包含网络和服务端排队/生成，并非供应商内部纯 TTFT。修改后这组还包含本地开发代理，两组不是受控性能对比，不能据此宣称模型变快或变慢。

三条修改版聊天均正常显示回复；没有云端 TTS 请求，没有原生英语 `start`，语音完成上报为 `error`，界面显示英语音色不可用。没有把这类快速失败当成低延迟首声。此前 localhost 直接访问后端的 CORS 预检被拒绝，未进入模型，已排除出计时；仅采用临时开发代理，没有放宽线上跨域配置。

为验证设备输出链路，单独用真实中文 Huihui 音色朗读中文作为对照：原生 `start` 等待 392.4ms，输出设备信号等待 535.8ms。两者相差约 143.4ms，说明原生开始回调不等于物理输出时刻。这是中文对照，不是英语聊天首声或人耳听感验收。
