# Chrome 识别长尾基线测量

日期：2026-11-05  
环境：Windows 11，Chrome `156.0.8078.75`，生产前端 bundle `index-Bq0RvOE-.js`  
固定音频：同一段 Windows Zira 点单 WAV，fake media 以 7.37s 循环输入。

## 结论

本轮**无法取得正常识别基线**：生产 ASR 当前返回 iFlytek `11201 licc failed`。因此流式收尾、整段重试、HTTP 回退、转写就绪和聊天首段没有可报告的基线，也没有伪造时长。

## 浏览器单调时钟证据

一次实际通话尝试（页面 `performance.now()`，单位 ms）：

| 时间 | 事件 |
|---:|---|
| 7708.7 | 请求 `/api/asr/session` |
| 8002.5 | session 返回 200 |
| 8004.4 | 打开直连 iFlytek WebSocket |
| 8220.4 | 发送首帧音频 |
| 8260.5 | 服务端返回 `code=11201` |
| — | 没有采集到 finalize 发送，也没有采集到 final |
| 14318.8 | `/api/asr` 返回 503 |
| 15128.9 | 观察到后端 relay WebSocket，但不能确认属于同一轮或由该 503 触发 |
| — | relay 没有可用转写，页面显示“这一句没接上” |

这组时间只能说明各事件发生过，**不是一条完整回退链**：没有记录“用户说完”时刻，也没有记录 `/api/asr` 请求起点；直连错误到 HTTP 503 的约 6.06 秒不能拆成回退各段耗时。HTTP 回退函数在 503 后也不会直接打开 relay，relay 的归属需要 interaction ID 才能确认。

通话在 `call.ts` 的 `handle()` 中会先生成并绑定 interaction ID，再进入 ASR；本轮只是**未采集到 interaction ID**，不能说没有产生。应当检查该轮 `/api/asr` 请求的 `X-Interaction-Id` 头。聊天请求没有发生是独立的观察。

## 服务端复核

连续三次直接调用生产 `/api/asr`，均返回：

```text
HTTP 503
{"detail":"iFlytek ASR error 11201: licc failed"}
```

这说明失败发生在 iFlytek 上游识别服务，而不是某条音频未被 VAD 检出。按项目使用的「语音听写（流式版）」官方文档，`11201` 是**日流控超限**；本轮尚未核对生产 AppID 的当日用量、上限和重置时间，也没有足够证据把它归因为授权失效或出口 IP 白名单。

## 影响

- 正常识别、流式超时、连接断开、不完整转写四种固定音频条件均**未采集**。
- 未能验证“明确失败时立即切换”能节省多少时间；也没有足够证据计算回退各段耗时。
- 本轮没有改生产付费配置，也不把服务故障归因于看板发布。
- 需要先核对生产 AppID 的当日用量、上限和重置时间；恢复额度后重跑同一固定音频。
- 本地已补 11201 结构化错误、停止同应用继续回退和“改用打字”提示的代码与模拟测试；这些改动留在语音分支，尚未发布。

## 恢复后的基线步骤

1. 同一 interaction ID 记录：
   - finalize 发送
   - finalize 成功/失败
   - 整段重试开始/结束
   - HTTP 回退开始/结束
   - 转写就绪
   - 聊天首段
2. 固定音频分别跑正常、流式超时、连接断开、不完整转写。
3. 不把整段重试与其内部 HTTP 耗时重复相加。
4. 明确失败时立即切换；单纯超时是否缩短，等正常收尾分布后再决定。
5. 验收转写完整、消息最多一次、不完整结果需确认、挂断后迟到结果不发送。

## 本地模拟验收（未发布）

已在语音分支补上结构化 `11201` 处理，未部署生产：

- 直连 WebSocket 收到 `code=11201` 时抛出 `AsrQuotaError`，不再尝试 relay。
- HTTP `/api/asr` 为 503 且 detail 含 `11201/licc failed` 时抛出同一结构化错误，不再继续回退。
- 额度冷却期内，后续调用直接返回 `AsrQuotaError`，不会重复上传音频。
- 通话和按住说话界面显示「今日语音识别额度已用完，可以改用打字继续。」
- 断连、超时、空 final 仍走原有恢复路径。
- 本地测试确认：
  - 配额失败后不再发第二次 ASR 请求
  - 迟到结果在挂断后不触发回复
  - 不完整转写不自动发送，仍需用户确认
  - 现有流式超时/断连恢复测试继续通过

测试结果：前端全量 **556 passed**，后端全量 **639 passed**，TypeScript/ESLint 通过。
