全链路的 900ms 判停本身约 949.5ms（最后有声 → finalize），没有异常；慢启动主要发生在浏览器朗读请求之后。当前证据不能区分：

1. 应用侧排队到 `speechSynthesis.speak` 的延迟；
2. 浏览器/native 在收到请求后到 `start` 回调的等待；
3. 本地/在线音色切换或合成失败后的回退；
4. 录音/回放环境导致的虚假延迟。
