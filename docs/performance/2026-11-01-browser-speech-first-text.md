# 取消讯飞朗读与首字等待验收（2026-11-01）

## 结论与当前边界

已取消产品中的讯飞朗读请求、预连接和自动回退，保留讯飞识别、发音评分及原有 Interview 评分、历史记录。默认使用浏览器整段朗读；本地 Kokoro 仍为主动选择的实验功能，不会自动下载。运行时代码为 `3bec4651ec4036cc4e56327a0e06a599f42138ff`，已合并、推送 main。

首字等待现在能分到提供方响应头、首个协议事件和首段正文。本批线上新回复主要等待上游正文，不能据此判定提供方内部排队或推理分别占多少。没有升级付费配置，也没有改变模型、提示词、thinking 设置、温度或输出预算。

**真实出声仍未验收通过。** 内置浏览器没有可用英语音色；本机 Edge 虽列出 Natural 音色，实际调用却在 `onstart` 前结束。直接调用浏览器 API 的最小对照也复现失败，详见下文。不能用模型耗时、`onend` 或过去的云端听感确认代替本次原生出声验收。

## 改动与兼容性

- 前端移除云端播放选项、TTS 请求函数和准备资源。旧版云端偏好迁移为浏览器，保留显式本地模式、个人音色、语速和音调。
- `/api/tts`、`/api/tts/stream`、`/api/tts/prepare` 统一返回 HTTP 410、`Cache-Control: no-store`，OpenAPI 标记废弃。不创建提供方客户端或 WebSocket，旧标签也不会继续合成。
- 无英文音色、启动失败和中途失败显示可关闭的错误提示；其他页面的朗读入口也能看到错误。取消和卸载仍释放资源，不回放已播过的部分。
- 独立审查发现的两项重要问题已修复：次级入口错误不可见；模拟面试朗读失败后仍开始计时。现在模拟题朗读失败或 20 秒超时会停在准备状态，明确提示并等待用户点击“开始回答”，尚不消耗 45 秒。
- ASR、发音评测、认证及学习历史服务实现未修改。保留旧云端遥测名称供历史记录解释；独立的遗留协议工具不再从产品 TTS 路由访问。

## 计时口径与复现方式

线上公共后端 `https://spoken-backend.onrender.com`，通过现有本机代理端口 12450，用 httpx 顺序请求 `POST /api/chat/stream`。先检查健康接口，交替提交同一组咖啡馆短历史与五轮历史，每次使用新的随机交互编号。真实生成新回复，不使用开场白缓存；没有请求音频、评分、登录或保存学习记录。

短历史为欢迎语加 `I'd like a cup of coffee, please.`。五轮历史按“点咖啡→小杯燕麦奶→询价→刷卡→外带要杯盖”构造，最后一句 `To go, please. Could I have a lid too?`。两批输入和调用配置相同，生成结果并非逐字固定。

- 客户端首字：开始请求到解析到首个非空 `delta.text`；全文：解析到 `done`。
- `llm_response_headers`：提供方请求开始到其响应头可用，累计时间。
- `llm_first_event`：提供方请求开始到首个非空 SSE 行，可能只是角色帧或心跳，**不代表文字**。
- `llm_headers_to_text`：提供方响应头到首个非空正文 delta，区间时间。
- `llm_keepalives_before_text`：首段正文前 `:` 注释行的计数；不据此反推内部排队。
- `response_ready`：应用收到请求到发出 SSE 响应头；不覆盖请求到达应用前的边缘等待和调度。
- 浏览器实际首声仅接受 `onstart`；本批失败时没有生成成功的 `speech.request_to_audio`。

诊断只保存固定数值字段、状态和随机关联编号；不记录消息正文、原始头、凭据或音频。表格汇总已保留，任务探针、临时数据库和原始工作日志在核对后清理。

## 真实聊天与原生朗读验收

使用本地同代码前端 `127.0.0.1:5184`、临时后端 `127.0.0.1:8018`，由实际聊天输入框发送新句子。该路径直连现有模型提供方，**不能和 Render 线上耗时混算**。

| 浏览器/交互 | 首字 ms | 全文 ms | 实际朗读结果 |
|---|---:|---:|---|
| IAB / `26c256e85a19061cf0e6f694e34d4f0b` | 382.1 | 525.8 | 缺英文音色，显示错误；`speech.complete=error` |
| Edge / `80b93bcba38dffc010098c391da464cb` | 527.7 | 756.6 | Ava Natural 在 4.1 ms 后结束但没有 `onstart`；失败 |

IAB 的后续新回复也可正常显示，错误提示可关闭，文字输入保持可用。Edge 手动重播、另选 Aria Natural 的试听同样出现 `end_before_start`。首次自动开场另记录过 `not-allowed`，不与真正发送后的错误混为一谈。测试中后端遥测未出现任何 TTS 请求。

为隔离产品队列，创建了只调用 `SpeechSynthesisUtterance` / `speechSynthesis.speak` 的临时对照页。英文音色就绪后为 47 个；点击事件 `isTrusted=true`、用户激活为 true、引擎 paused/speaking/pending 均为 false。用 Ava、语速 1.1/音调 1.05，6.4 ms 后仅收到 `end`；浏览器默认参数也是 4.1 ms 后仅收到 `end`。两次均无 `start`、`charIndex=0`。这证明当前本地原生 API 对照也失败，尚不足以判定 Microsoft 服务、浏览器或本机环境中哪一个环节异常。

正式站 Edge 标签已打开，但页面读取超时，之后工具报告调试连接未附加，截图与进一步控制受阻。**没有获得正式站原生朗读的成功计时或新听感确认**；不能宣称浏览器首声几乎为零。没有更改音量、麦克风权限或系统/浏览器安全设置；测试音色修改仅发生在 localhost 测试源，未修改正式站偏好。
