# 可靠性修复与性能验收 · 2026-11-01

按已确认顺序完成收藏、保存、重复计数和旧响应修复，再处理图片、统计与跟读等待。使用现有配置，不增加付费服务。

## 修复范围

- 收藏与删除表达明确意图，按词串行处理写入；刷新、删除后重加、失败回滚均有回归覆盖。
- 单词复习确认保存后才切下一张；失败保留原选择和重试编号，未落库的词不进入复习。
- 面试和跟读的保存失败可见，重试复用编号，保留现有评分；后端按用户事务去重，冲突返回 409。兼容旧请求、游客认领及已裁剪的历史。
- 历史详情的成功、失败及 loading 收尾都核对当前选择与账号，阻止旧响应覆盖。
- 独立复核发现并补修：删词重加后的旧复习编号残留，以及过期掌握状态导致错误回滚。
- 长跟读文本的保存标题按 Unicode 字符限制在 200 字以内，全文另存，避免评分成功后反复收到 422。参考文本的 2,000 字限制前后端保持一致。

## 学习统计

同一进程对照已提交旧实现与新实现。SQLite 合成数据：1,000 个不同日期和词，按事件数扩展；每组 3 次，计入 owner 锁、统计和回滚，不计插入数据。

| 事件数 | 旧实现中位数 | 新实现中位数 |
| --- | ---: | ---: |
| 1,000 | 8.93 ms | 7.66 ms |
| 10,000 | 72.30 ms | 18.30 ms |
| 50,000 | 488.76 ms | 75.93 ms |

新实现不加载逐条事件 ORM 对象，一次 journal SQL 返回汇总行和按本地日期分组的行。正常已有数据的读取仍为 4 条语句，避免增加远程数据库往返。SQLite 仅缓存有界的纯日期转换，未缓存用户统计结果。

时区、夏令时、半小时/45 分钟偏移、永久徽章、历史迁移和游客认领均有回归覆盖。PostgreSQL 转换语句已编译验证；当前本机配置为 SQLite，未将其表述为线上 PostgreSQL 实测。独立本地 HTTP 小数据验收为 16.64/17.70/32.37 ms，和上表不同口径。

## 跟读等待

改为录音时上传评分音频，停止时只处理尾帧并等待结果；保留旧 POST 兼容入口。并发接收供应商错误、设置截止时间，取消时释放麦克风、音频上下文和连接。讯飞仍用于识别和评分，未恢复讯飞朗读。

服务端独立接收消息，在上传积压和等待最终结果时也能观察断开，及时取消评分任务。接收缓冲限制为 512 KiB/4,096 帧，超限明确失败；保留结束标志位置，不阻塞接收者去隐藏断开事件。

对照使用[讯飞官方 SDK 公开 PCM](https://github.com/iFLYTEK-OP/websdk-python-demo/blob/main/xfyunsdkdemo/speech/resources/ise/read_sentence_en.pcm)，原样本 2.722 秒，长样本为其连续重复 8 次。分别调用真实讯飞评测，每种长度各一组对照；录音时间不计入“停止后等待”。

| 音频时长 | 旧方案停止后等待 | 新方案停止后等待 |
| --- | ---: | ---: |
| 2.722 s | 12.377 s | 1.755 s |
| 21.776 s | 26.819 s | 3.103 s |

长样本中，停止后上传尾部约 1.672 秒，取得结果并关闭连接约 1.431 秒。连接耗时约 0.17–0.19 秒。短样本旧方案上传后有约 9 秒额外等待，单次对照不能将供应商与关闭波动全部归因于代码。短样本两次均为 98.9 分；长样本为 94.6/99.5 分，供应商评分存在波动，不能承诺逐次分数一致。

Edge 页面另用公开音频构造 MediaStream，经过实际录音组件、AudioWorklet、WebSocket、真实讯飞评分和历史保存：约 417 ms 开始传音频，停止后约 2.66 秒显示 94.2/100，保存一次且返回 201。未使用物理麦克风或检验播放听感。流式 PCM 与整段转换在 8/16/22.05/44.1/48/96 kHz 下逐字节对齐。
