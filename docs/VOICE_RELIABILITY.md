# 语音可靠性与延迟修复

目标：保留现有录音、通话、本地引擎和文字练习，减少结束说话后的等待；失败时保留整句录音，不把半句作为最终回答。

2026-10-27 的实测显示，同样合成音频在本地连接讯飞时识别约 2–3 秒，经过生产 Render 后端时约 8–15 秒。前一轮仅调整连接与超时的修复不足以解决生产链路延迟。

## 实施选择

- 继续使用当前海外中转：部署简单，保留为兜底；无法消除额外的音频传输路径。
- 浏览器直接连接讯飞，后端签发短期连接授权：作为本次实现选择；不使用浏览器内置识别，API Secret 只留在服务端，授权不写入持久存储或日志。
- 迁移后端区域：需要额外云端资源和部署决策，不在本次修复中直接执行。

直连只改变传输路径，维持现有 16 kHz 单声道 PCM、英文识别和 UI。浏览器连接失败时继续使用既有后端；一段时间内跳过重复失败的直连尝试。讯飞业务错误不无限重试，用户取消操作立即释放连接。

## 实施与验收顺序

1. 先用失败用例覆盖短期授权的缓存与密钥边界、直连帧序列、完整转写、取消与失败兜底。
2. 实现后端短期授权接口、共享的浏览器直连客户端，接入录音和实时通话，保留原中转路径。
3. 完整运行前后端测试、代码检查和构建，独立审查后推送 main。
4. 确认前后端部署引用同一代码提交，再进行生产实时/录音识别和隔离浏览器点击验收。
5. 如自动注入合成录音测试采集流程，明确标记为合成测试；真人麦克风、实际听感按用户当前安排暂缓，不能伪报通过。

前一轮已经补齐：有限连接重试、连接关闭等待限制、完整录音兜底、超时/错误连接退役、短音频结束标记与空结束帧文本保护。最终生产结论与保留测试数据记录见 `design-qa.md`。
